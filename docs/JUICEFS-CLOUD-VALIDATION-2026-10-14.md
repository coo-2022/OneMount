# JuiceFS 网盘后端验证 · 2026-10-14

分支：`feat/juicefs`。环境：Windows 11 x64、WinFsp、JuiceFS 1.3.0，以及本分支构建的 rclone v1.75.0-onemount。

## 数据通路

Windows 盘符 → JuiceFS → 本机认证 S3 网关 → rclone 网盘后端 → 连接内的 `.cloud-island/<磁盘 ID>`。

文件名、目录结构、空文件与稀疏区域保存在本机 SQLite 元数据中，网盘保存块对象。网关关闭异步 VFS 缓存；后台上传仅由 JuiceFS 管理。默认不开启后台上传。

## 本次修复

- 百度网关初次启动时缺少父目录，导致存储桶创建失败。改为先通过连接根目录创建独立卷目录，再启动范围受限的网关，并开放百度文件系统卷入口。
- 初始化失败会留下 SQLite 数据库及 WAL。初始化意图先持久保存，重试使用 `--no-update` 并核对卷身份；数据库与 WAL 保持原位。已有未知元数据或丢失的已初始化元数据均不会被自动覆盖。
- OneDrive 后台上传实测触发慢请求重试与上传会话冲突。网关同一 key 的 PUT/DELETE 改为互斥，旧请求失败清理不能跨越新上传；已取消的等待请求不会写入。父目录创建串行执行，修复并启用 `--no-cleanup`，保留删除块后留下的空目录。OneDrive 卷同时上传的块数设为 1。
- 百度的零字节限制仍保留在直连后端；文件系统卷中的空文件和截断通过元数据表达，界面不再显示直连专属提示。

## 验证

应用单元测试 59 项全部通过。真实本地 WinFsp 回归覆盖直连、JuiceFS 默认模式、后台上传模式，并额外验证网关不可用时初始化失败、恢复网关后在同一卷重试成功。

S3 网关回归通过：旧 PUT 失败与新 PUT 竞争、取消重试、父目录保留/清理，以及既有路径越界保护。实际 Windows 预览包的界面测试通过：网盘切换保留卷模式、创建卷、默认关闭后台上传、百度直连提示范围与渲染错误检查。

真实账号矩阵由 `scripts/windows-cloud-volume-integration.cjs` 执行，结果汇总见 [验证结果 JSON](JUICEFS-CLOUD-RESULTS-2026-10-14.json)。六组全部通过，测试会话均已安全停止：

| 网盘 | 默认模式 | 后台上传模式 |
| --- | --- | --- |
| 百度网盘 | 通过 | 通过 |
| OneDrive | 通过 | 通过 |
| Google Drive | 通过 | 通过 |

每种组合均使用新的独立卷，覆盖：

- 4 MiB + 137 字节跨块随机数据及 SHA-256 校验，中文和空格路径。
- 空文件、稀疏文件、随机位置覆盖、追加、重命名、截断为零、删除。
- 两次安全卸载、备份干净缓存、重建 Manager 并重新挂载；从网盘回读校验内容和目录状态。
- 固定网关端口、实时待上传指标、最终远端块存在性与退出后盘符消失。

测试不复用用户正在使用的盘符；原有文件不被改动。测试卷及本机测试目录保留供核对，账号配置和原始日志不提交到 Git。

## 边界

这是单机 SQLite 元数据卷，不提供跨设备同时写入或元数据恢复向导。不能直接从网盘客户端编辑块对象。慢网络仍可能需要等待上传完成后重试安全卸载；失败时保留网关、会话、元数据和缓存。

本次没有验证真实配额耗尽、长时间断网、长期令牌刷新、跨设备恢复或全套 S3 协议兼容性，也没有构建 Linux 版本。
